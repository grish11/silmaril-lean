# TLA+ semantic coverage

This inventory covers the mathematical data and operator work, named source
passes, and their interfaces to standalone TLA. It records the evidence at
`11e5878ccb2a500a18ee4494134396a454cbbb61` on `main`, observed on
2026-11-25. Update a row when its corresponding artifact lands. A parser
fixture, a Lean value law, and a theorem about a behavior establish
different claims. [Baseline](https://github.com/hiloopai/silmaril-lean/tree/11e5878ccb2a500a18ee4494134396a454cbbb61)

| Evidence | What counts here |
| --- | --- |
| **Mathematical laws** | A definition over a specified carrier and checked Lean statements about it. A caller-supplied law or interpretation remains a premise when a result uses it. |
| **Surface and source** | Parsing produces a Surface tree. Resolution identifies declarations by ID and home path. Level checking classifies resolved expressions. Lowering produces a denotation for a supported selection. Each gate has its own profile. |
| **Checked examples** | A named parser, Lean, or integration regression exercises a stated case. Intact upstream bytes and in-memory reproductions are identified separately. |
| **Finite execution** | A decision or enumeration runs under a stated finite contract. Bounds control the meaning of the result. |
| **Temporal entailment and proof** | A checked theorem over already interpreted behaviors, or evidence for a source theorem if a source proof has actually been checked. |

## Tagged values and reference fit

| Convention | Relation to the reference and proof scope |
| --- | --- |
| Pure sets and separate tagged kinds | The book presents pure ZF membership and extensional equality on the full value universe in §16.1.6. The pure-set `Data.Model` realizes that interface with raw `ZFSet`. Tagged `Value` distinguishes set, integer, Boolean, graph and character encodings. It uses set extensionality with recognized set operands. The raw tagging code is a Lean representation. Cross-kind equality, disjointness, and the absence of members of a non-set value in the tagged relation are claims about this interpretation. |
| Opaque values and set size | Raw codes outside the recognized images remain possible values and unbounded witnesses. Tagged sets can contain values of any kind, including opaque codes. Their payloads are mathematical sets of codes. Separation and image are bounded by a supplied set, and powerset ranges over its subsets. The pure-set no-universal-set theorem and the tagged existence of a value outside each set are checked individually. |
| Graph, tuple, record and string identity | One graph tag represents functions. Equality compares exact domains and outputs. Tuples use integer domains and records use string keys. Strings are tuples of character values, matching §16.1.10, so the empty string is the empty tuple in this interpretation. TLC represents strings as their own tool kind and can enforce representation-specific argument checks. Graph and string equalities therefore need carefully matched oracles. |
| Boolean interpretations | The book requires the moderate guarantees and permits the liberal interpretation. Tagged `isTrue` means equality with `TRUE`, and tagged negation and conjunction use liberal truth. DataElab has a separate caller-supplied `holds` and invalid-operation interface with Boolean and absorbing-value cases. Binding that interface to tagged values requires an explicit policy for invalid guards and operands. With tagged membership, an unrecognized bound gives a false existential, vacuous universal and no-witness bounded choice. |
| Stable unspecified results | Equality of arguments suffices for stability of the selected model’s functions. Tagged arithmetic, graph operations and path updates use a configurable `Unspecified` function of the operation and its operands where applicable. The integer slice includes reflexive `≤` even outside the embedded integers and the checked remainder equation for positive integer divisors. Choice depends on the predicate’s extension and has its own shared no-witness value. Out-of-domain graph application uses the chosen policy. Updating a recognized graph at a missing key preserves the graph. A non-function `EXCEPT` step composes the tagged application and update policies, while TLC can reject it. |
| Mathematical and source interpretation | Proofs about a particular carrier or explicit primitive policy inherit those choices. A source-semantic correspondence theorem must specify the admitted model laws, Boolean profile and syntax. The current APIs support representative checked equations. Whole-language correspondence with the book, SANY or TLC remains open. |

## Temporal handoff and proof boundary

`DataBridge.scope Rigid Flex` specializes General TLA to one chosen value
carrier. For a source module, the proposed bridge specializes one fixed
model and policy throughout a run, with a rigid assignment by declaration ID
and one flexible valuation per instant. A state expression evaluates from the
rigid environment and one state. An action evaluates with one rigid
environment and an ordered source/target pair, and an observation compares
values by Lean equality. The bridge already consumes such denotations.
The named DataElab path currently yields only a state value.
[Data bridge](tla-data-bridge.md) · [Scoped General TLA](tla.md#scoped-general-tla)
