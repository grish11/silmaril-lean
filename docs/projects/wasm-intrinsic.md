# Intrinsic Core Wasm

`Silmaril.Wasm.Validation.Intrinsic.Defs` provides proof-relevant Wasm syntax:
`Body context effect` records input and output stacks, local initialization,
composition, subtyping, and framing. Structured instruction bodies live under
the right label context (loop inputs or block results). Local, direct function,
and simple branch references carry their lookup at the right type. `return`,
`br` and `unreachable` have the same polymorphic stack effects as the existing
typing rules. `Function` retains the source type index and local declarations.
The module environment includes imported and defined functions in index order,
and preserves all original non-function declarations and exports.

This is a representation of the **existing Core typing judgments**. The
specialized constructors do not cover every atomic family: for example SIMD,
GC, memory, indirect and tail calls, and cast/table branches use proof-carrying
atomic leaves. Such leaves cannot contain a block, loop, if, or try-table body.
These operations are not excluded from the lifting theorem: their exact Core
typing rule suffices to construct the corresponding typed leaf.

`Intrinsic.Thms` proves erasure soundness for `InstrsOk`, `FuncOk` and `ModuleOk`,
and existence of a lift erasing to each well-typed raw value. `Function.equiv`
and `Module.equiv` use equality of raw erasures as the quotient relation. This
forgets exactly the choices of representation that the original value cannot
observe (e.g. wrapping an empty body in an empty stack frame); it does not
quotient by behavior, validator acceptance, or equality of metadata subsets.
The inverse uses classical choice on the existence theorem. It is not a
computable elaborator or a canonical choice of typing tree.

The [structural-reference and generic module AST](wasm-inductive-generic.md)
has an exact witness-preserving specialization back to this representation.

## Building and checking terms

Import `Silmaril.Wasm.Validation.Intrinsic.Quote` to publish an explicit typed
term with `wasm_intrinsic name : interface := body`. This checks the supplied
intrinsic constructors, not binary input. `wasm_prove_erasure eqName : name => raw`
is optional and works from a separate importing module, including for `raw`
generated by the plain Wasm quotation command. It kernel-checks exactly
`name.erase = raw`, with no native fallback. This is independent of both
`name.sound` (intrinsic well-typedness) and `wasm_prove_source` (source agreement).
For automatic file quotation on a checked straight-line subset, see
[Quote a Core Wasm file as an intrinsic module](wasm-intrinsic-file.md).

## Reproduce

```sh
bash tests/wasm/intrinsic/check.sh /tmp/wasm-intrinsic
```

The fixture is a function that uses `local.get` and calls an imported function
inside a result block. Compare explicit raw and typed constructors; import and
query the same raw body length (through erasure for the intrinsic object); and
prove the same `ModuleOk raw interface` using kernel validation or intrinsic
soundness plus exact erasure. The script measures process time and RSS under a
15 s timeout and a 4096 MiB Lean allocator limit, and records the standalone
fixture `.olean` sizes (not closure size). It checks a typed-reference negative
case, an imported erasure theorem, a quotient round trip, and the axiom audit.

On one warm run, raw / intrinsic wall times were 3.05 / 3.20 s to construct,
3.17 / 3.01 s to import, 2.98 / 3.03 s for the query, and 3.07 / 3.10 s for
the typing proof. All were about 2.07–2.09 GiB RSS. Standalone fixture sizes were
21,048 and 53,192 bytes. Imports dominate this tiny case; the timings do not
establish a speedup, and the size ratio does not predict larger modules.

Section-indexed/chunked certificates split **binary decoding**, not typing or
stack indices. They can certify the raw side of the erasure theorem, but do not
provide a competing representation for this typed lookup or proof workload.
