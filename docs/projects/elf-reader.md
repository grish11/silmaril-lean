# The per-part ELF reader and the explorer's ELF tab

Every part of a pinned ELF file, checked by the kernel on the file's exact bytes, and shown in the
explorer with its bytes and an (unverified) disassembly.

## Statements

`Silmaril.Elf.Staged.Reader` (`Defs`, `Thms`; proofs in `Silmaril.Proofs.Elf.Staged.Reader`):

| name | meaning |
|---|---|
| `kread x` | the byte oracle of kernel bytes `x : KBytes` (`KBytes.readLE`) |
| `window ws r` | the reads of `r` restricted to the byte ranges `ws` |
| `PartIs F ws p v` | the ELF specification's reader `p` (`Parse.header`, `Parse.phdr o`, `Parse.shdr o`, `Parse.strAt`, `Parse.body`, `readLoader`, `readLayout`), run on the bytes of `F` **inside `ws` only**, returns `v` |
| `ZerosAt F o n` | the `n` bytes of `F` at `o` are zero |
| `sub_kbytes` | `x.wf → x.toByteArray = raw → Check.Sub (kread x) (blobOf ⟨raw⟩)`: kernel bytes answer as the raw file |
| `partIs_of_kbytes`, `zerosAt_of_kbytes` | a part of the raw file from one `decide +kernel` run on its kernel bytes |
| `PartIs.run`, `.layoutIs`, `.bodyIs`, `.loaderIs` | a part as a fact of the specification (`p.run (blobRead F) = some v`) and of the staged parse (`Silmaril.Elf.Staged`) |

`F` is `blobOf ⟨raw⟩` with `raw := include_bytes …`, and `x` is `kbytes_def K of_include raw`
(`Silmaril.Data.IncludeBytes.Kernel`), whose `K.toByteArray = raw` the kernel checks by comparing
chunk literals. So each part is a statement about the raw file. The windows are part of the
statement; `Silmaril.Elf.Staged.Reader.Examples` shows that a narrower window, another part's
window, a different claimed value, truncated or malformed files, ELFCLASS32 and big-endian files
are refused.

## Pinned files

`Silmaril.Elf.Staged.Pinned.{HelloGcc,Sha256sum}.{Bytes,Defs,Thms}`, generated by
`scripts/elf-reader/gen.sh` (`elf-staged emit-reader`) from the files of
[examples/elf](../../examples/elf/README.md): GNU coreutils 9.4 `sha256sum` (Ubuntu
9.4-3ubuntu6.3, 39,336 bytes) and `hello-gcc` (15,960 bytes). For each file, `Thms` has

* `header`, `phdr_i`, `shdr_i`, `name_i`, `body_i`, `loader`: one `PartIs` each, with the
  reader's exact footprint (computed by the emitter with `Parse.trace`) as windows;
* `pad_k`: one `ZerosAt` for each byte range that no section occupies and no part reads;
* `layoutPart`/`layout` (`LayoutIs F L`) and `parses : Parses F (L.assemble bodies ld)`,
  assembled from the parts by `Staged.parses_assemble` with no further run of the reader.

All 125 theorems of each file use only `propext`, `Classical.choice` and `Quot.sound`; no native
evaluation. Measured with `lake env lean` (this includes about 3.5 s of imports per module):
`Sha256sum/Thms.lean` 6.9 s, `HelloGcc/Thms.lean` 6.1 s.

**Coverage** (from the theorems' windows, every byte of the file):

| file | decoded | checked zeros | raw | unknown |
|---|---|---|---|---|
| `gnu-sha256sum` (39,336 B) | 8,516 | 3,514 | 27,306 | 0 |
| `hello-gcc` (15,960 B) | 5,510 | 9,556 | 894 | 0 |

*Decoded* bytes are read by a checked part. *Raw* bytes are inside a section or loaded segment
but are not decoded: code, `.rodata`, `.data`, `.eh_frame`, `.got`, init/fini arrays, and
string-table bytes that no part reads. They are payloads that the specification keeps as byte
ranges (`Body.progbits`, `.strtab`, `.other`).

**Not supported, listed rather than omitted:** ELFCLASS32, big-endian files, extended section
numbering and compressed sections. These are refused or read as no sections, never misread. Any
`e_machine` is accepted and recorded. The specification does not check alignment, overlap, or the
agreement of the section and loader views (`Silmaril.Elf.Lookup.DynConsistent`). Stripped files
have no `.symtab`, so only `.dynsym` is listed. A file with no section header table has no
sections, but its program headers and loader view are still read.

## Explorer

`tools/elf-pages` (`make pages`) writes `elf/index.json`, `elf/f/SLUG.json`, `elf/dis/SLUG.json`
and `elf/blob/SLUG.bin` next to the page. It imports the built `Thms` modules and **reads each
theorem's statement**. The part a theorem is about comes from the claimed constant's place in `L`,
`bodies` or `ld`, as defined in the environment. Its bytes come from the windows in the statement.
Its status and axioms come from `collectAxioms`. Theorem names and metadata are never used. The
tool re-runs each reader natively on its windows as a consistency check. It refuses any statement
of another form or about another file. `elf-pages --verify DIR` regenerates the data and compares
it. `scripts/elf-reader/test-pages.sh` checks that `--verify` rejects these edits to the data: a
moved window, a re-associated theorem, a widened coverage class, hidden axioms.

The ELF tab (`tools/silmaril-project/src/project/explore/views/elf.js`) has these pages:

* `#/elf`: the files, with theorem counts, axioms and coverage;
* `#/elf-file/SLUG`: identity and provenance (with an in-browser SHA-256), the coverage map, the
  header, program headers (file and memory extents, zero-filled memory), sections (segment,
  body kind, header, name and body theorems), the loader view, symbols and the unsupported list;
  `#/elf-file/SLUG/theorems` lists every theorem with its windows and axioms;
* `#/elf-bytes/SLUG/OFFSET[/LEN]`: 4 KiB pages of bytes coloured by coverage, with file offsets
  and virtual addresses. Selecting a byte shows its section, segment, and the theorems whose
  windows hold it. You can jump by offset or by virtual address;
* `#/elf-disasm/SLUG[/ADDRESS|SECTION]`: the committed GNU objdump listing, under a fixed
  **UNVERIFIED** warning. Each row's bytes are checked against the file. Addresses link to the
  byte view. No theorem is about the decoding.

Checks: `make elf-check`, run by `make check` when `elf-pages` is in scope, checks the pins,
regeneration and the tamper test. `tools/silmaril-project/tests/explore/elf.mjs` runs in the
Pages workflow's browser tests.
