# Parquet PLAIN physical values

Import `Silmaril.Formats.Parquet.Plain.Defs` for the executable codec or
`Silmaril.Formats.Parquet.Plain.Thms` for its contracts. This codec consumes one
already delimited PLAIN values payload in `Silmaril.Formats.Bytes`. The caller
supplies the physical value count and, for a fixed-length byte array, its
schema width. See the [Arrow and Parquet coverage guide](arrow-parquet-coverage.md).

The wire rules are pinned to **apache-parquet-format-2.14.0** at commit
`04d56f291ff963e98bc37ab8100e2fc133ff583c`. The SHA-256 of the raw
`Encodings.md` is
`b6b980c67acc14d3e9e4b592c582523b5dc2cc09ad9f90bc2b1912df461e5c88`.
[PLAIN wire specification][spec] · [Physical types and schema widths][idl]

## Wire and reader profile

| Physical type | Wire bytes and API |
| --- | --- |
| `INT32`, `INT64` | Four or eight little-endian octets per signed two's-complement word. Use `decodeInt32` or `decodeInt64` and the corresponding typed writers. The checked writers `encodeInt32Checked` and `encodeInt64Checked` reject any unbounded input outside the signed width before conversion. |
| `BOOLEAN` | Value `i` is bit `i % 8` of byte `i / 8`, LSB first. `decodeBoolean` requires exactly `(count + 7) / 8` bytes. It ignores only the unused high bits of the final byte. `encodeBoolean` sets those bits to zero. An external count is necessary because the same byte length can represent several Boolean counts. |
| `FLOAT`, `DOUBLE` | Four or eight little-endian octets of IEEE 754 bits. `decodeFloatBits` and `decodeDoubleBits` use `UInt32` and `UInt64`. The readers and writers preserve every bit, including signed zeros, infinities, and NaN sign and payload bits. |
| `FIXED_LEN_BYTE_ARRAY` | Consecutive byte strings of the same schema width. `decodeFixedLenBytes` and `encodeFixedLenBytes` admit widths from 1 through `2^31-1`. The writer checks each element's width. |

The fixed-width readers require exactly `count * width` bytes and have zero
padding. Zero values require an empty slice. A shorter slice yields
`.truncated`, and a longer slice yields `.trailingBytes`. Size calculations
use Lean `Nat`, so counts and products cannot wrap. The readers check size
before allocating decoded values. A page reader can enforce any lower
resource cap before calling this codec.

Variable `BYTE_ARRAY` uses a four-byte little-endian length per value and
remains outside this slice. Deprecated `INT96` uses twelve little-endian
octets and has no codec entry point here. The slice leaves timestamp
interpretation, pages and footers, dictionary and RLE encodings, definition
and repetition levels, compression, and logical annotations to their
respective layers.

## Theorems

- `decodeFixedWidth_ok_iff` specifies the exact partition of the entire
  input into the requested number of equal-width words and the corresponding
  ordered results.
- `decodeInt32_encodeInt32`, `decodeInt64_encodeInt64`, and
  `decodeFixedLenBytes_encodeFixedLenBytes` establish the corresponding
  round trips. `encodeInt32Checked_eq` and `encodeInt64Checked_eq` specify
  the representability checks and overflow result.
- `decodeFloatBits_encodeFloatBits` and `decodeDoubleBits_encodeDoubleBits`
  establish bit-pattern round trips for arbitrary input words.
- `decodeBoolean_ok_iff` specifies exact consumption and indexed bit order.
  `encodeBoolean_length` and `encodeBoolean_bit` specify the writer's length,
  data bits, and zero padding. `decodeBoolean_encodeBoolean` establishes the
  round trip for arbitrary Boolean lists.

## Independent fixtures

The [fixture manifest][vectors] contains six unframed PLAIN payloads. It was
generated by the Apache-2.0 parquet-java **1.16.0** low-level PLAIN writers at
commit `402c3810c372d29603e181771acebfecc71bef61` and read back by the
corresponding parquet-java readers. The SHA-256 of the manifest is
`8fab794295cdfd337f6555f8dab12ab59416217087d16c48e196916239209db2`.
The fixture program records the values, fixed width, and writer options.
Lean checks the manifest against the literal payloads and checks both
directions on those bytes. Additional Lean cases cover nonzero Boolean
padding, NaN payloads, truncation, trailing data, overflow, and bad widths.
The NaN cases are hand-derived because parquet-java's floating-point writer
canonicalizes NaNs. [Oracle program][oracle] · [Pinned writer sources][writers] ·
[Lean fixtures][lean]

Run the oracle with JDK 17 or newer. Give the shell variable `jars` the path
to a directory containing these artifacts from [Maven Central][maven].
