# Flat PLAIN Parquet column and row-group scan

`Silmaril.Formats.Parquet.FlatScan.Defs` assembles flat required or optional
uncompressed PLAIN INT32 columns from a plaintext Parquet file snapshot.
The scanner uses the [typed footer](parquet-footer.md) and
[page framing](parquet-page-framing.md) for offsets and the on-disk payload
spans. It checks a scalar page callback at the row-slot boundary.

## Checked input and output

- `scanFileRowGroup` reads the footer, checks its file version and the total
  row count against the nonnegative row-group counts, and selects a group
  by ordinal. `scanRowGroup` also accepts already decoded metadata and the
  corresponding footer start from the caller's immutable snapshot.
- The flat schema has one root with the advertised number of immediate
  children. Each leaf has physical type INT32 and REQUIRED or OPTIONAL
  repetition. Names must be distinct. The group has exactly as many
  column chunks as the schema has leaves. Each chunk must match the
  one-component path and physical type at its position. This rejects
  duplicate, missing, extra, and reordered column metadata.
  `flatSchema` exposes the ordered names and layouts for open-time binding,
  including for a file with no row groups.
- Each column must advertise the group's row count as `num_values`, use
  codec 0 (UNCOMPRESSED), and admit only PLAIN and RLE in its encoding list.
  Nonempty columns must advertise PLAIN. The scanner rejects dictionary
  and index offsets and rejects every framed kind other than data V1 or V2.
  Page sizes must fit the caller's budget and the compressed and uncompressed
  sizes must agree. CRC-bearing pages are rejected.
- PLAIN is required for page values. V1 must advertise RLE for both level
  encodings. V2 must have one value slot per row, no repetition section,
  and no definition section or nulls for a required leaf. The callback
  receives the checked data-page header and the exact on-disk payload bytes.
  It owns level and scalar byte consumption and the meaning of the values.
  The scan checks the returned slot count for each page, excludes nulls for
  required leaves, and checks the V2 null count. It consumes the chunks in
  page order and checks the sum of page slots against the column count.
- Successful columns carry their checked row count. `Batch.rows` zips the
  columns without changing row order and returns the advertised number of
  rows, including empty rows for a zero-column batch. The caller can cap
  rows, columns, total cells, bytes per page, and the framing lookahead and
  page count. The default caps are 1,048,576 rows, 256 columns, 16,777,216
  cells, and 16 MiB per page.

This profile leaves logical annotations uninterpreted. It excludes nested
or repeated leaves, other physical types, compression, checksum verification,
dictionary decoding, page index and statistics interpretation, inter-column
chunk-overlap checks, and Arrow events. Deprecated offsets and byte totals
unrelated to the selected chunk extent have no role in the scan.

`Silmaril.Formats.Parquet.FlatScan.Scalar.Defs` exposes the ready-to-run
`decodeInt32Page` callback. Use
`scanFileRowGroup limits (decodeInt32Page scalarLimits) file groupIndex`.
It translates the checked header and flat level schema into
`ScalarPage.Parameters` and calls `ScalarPage.decode`. Level processing,
decompression policy, and physical decoding remain in the scalar adapter.
[Flat definition sections](parquet-flat-page.md) · [Physical PLAIN values](parquet-plain.md) · [Scalar page adapter](https://github.com/hiloopai/silmaril-lean/pull/4423)

## Lean contracts

The public theorem header gives `column_count`, `rows_length`, and
`scanRowGroup_dimensions`. The first records the number of accepted slots in
one column. The other two prove the row count of assembly, including zero
columns, and both dimensions of a successful scan against the row-group
metadata. These count guarantees apply to any callback.
[Theorem header](../../Silmaril/Formats/Parquet/FlatScan/Thms.lean)

## Independent fixtures

Both files were generated by PyArrow **26.0.1** from a required INT32 column
`required_i32` with `10*i - 17` and an optional INT32 column `optional_i32`
with `-3*i` except for null at multiples of three, for `i` from 0 to 23.
The writer uses 12-row groups, batch size 4, `data_page_size=1`, codec NONE,
and disables dictionaries, statistics, and page checksums. Each file has
12 data pages across two columns and two row groups. PyArrow read back the
expected rows and Apache Thrift **0.25.0** independently identified each
exact payload window. A native test callback compares the received bytes
with those windows and supplies the corresponding oracle slots. The test
also runs the scalar adapter on both files and compares every decoded row
with the oracle, in order. Rejection cases cover malformed metadata, unsupported page
kinds and encodings, CRC rejection, count mismatches, and the zero-column
case. [PyArrow release pin][arrow] · [Fixture regression](../../tools/parquet-flat-scan/ParquetFlatScanRegression.lean)
