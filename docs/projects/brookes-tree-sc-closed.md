# C3 completed Brookes behaviors

Import `Silmaril.Semantics.Brookes.TreeSC.Closed.Thms` for the comparison
between finite completed Track A read/write paths and return-bearing Brookes
behaviors. The underlying [TreeSC replay][replay] supplies store-aware frames
and the [Brookes core][brookes] supplies stuttering, mumbling and bind.

## Observation and replay

`treeBehavior` and `forestBehavior` generate behaviors from `Returns` and
`ForestReturns`, respectively. They existentially quantify the contextual
start and end stores and use the unconstrained `openGap` before each
primitive. Each nonempty frame list contributes its `(before, after)` pairs
in order via `Frame.transition`. A successful path with no frames contributes
one identity at its store via `returnTrace`. The result is carried through all
rewrites. A prefix without a witnessed return supplies no seed.

`treeBehavior_eq_machine` uses TreeSC's `returnTrace_iff_machine` before
applying `Behavior.generate`. It identifies the entire saturated behavior of
the weak ITree for `Code` with the behavior generated by completed raw machine
replays. An accepted word on either side has a finished generator and a
Brookes deduction from it. The resulting word can contain inserted stutters
or contracted segments.

The singleton projection gives a separate exact result.
`treeBehavior_completes_iff` recovers a path with equality gaps at fixed
initial and final stores. It uses `Behavior.completes_generate_iff` to recover
a contiguous generator and restores those store endpoints on the original
tree path. `denote_completes_iff_sc` uses the TreeSC replay theorem to identify
this projection with completion in the singleton SC scheduler, existentially
hiding its event word.

## Composition, choices and results

`machineBehavior_eq_denote` and `treeBehavior_code` give the following
equations on full closed behaviors.

| Code form | Behavior |
| --- | --- |
| Done | `Behavior.ret ()` |
| Load | `readBehavior loc` bound to the continuation selected by the pre-store's value |
| Store | `writeBehavior loc value` bound to the continuation after updating the cell |

The atomic prefix proof splits the first `MachineStep` from the rest of the
replay. A nonempty continuation may begin at any store. If the continuation has
no actions, the extra return identity can be inserted by stuttering and
contracted at the prefix post-store by mumbling. Conversely, an identity at
any store from an empty continuation is admitted as a stutter. Both primitive
access modes have the same store effect in this fragment.
`treeBehavior_seq` proves exact sequencing under `Command.seq`, using
substitution at done, the left unit law and associativity of Brookes bind.

`forestBehavior_eq_union` gives existential union over arbitrary forest roots.
`choiceBehavior_eq_union` identifies a one-shot TreeSC choice with the union
of the selected programs' saturated behaviors. `treeBehavior_branch` gives
the same union law for an arbitrary existing coalgebra at any node unfolding
to a branch. It moves the first silent selection into or out of the witnessed
path. The theorem applies successively to nested choices and covers zero
alternatives. Both delayed and stepping branches use Track A's weak policy.
`treeBehavior_refines` transfers Track A observational refinement to inclusion
of accepted words and results. `treeBehavior_map` commutes with terminal-value
mapping on any coalgebra, carrying the same frames and deductions into the
direct image of the result.

The [regressions][regression] use an open join to run a write of `1` followed
by a load that can see an environment's `0` and write `2`. The saturated
behavior contains a gapped word for that run and rules out its singleton
completion from `0` to `2`. They also check nested choices with distinct Boolean
results, a natural-number result map, and explicit deadlock and divergence.
A zero-way choice and a self-loop have equal completed behaviors. Track A
observes deadlock at the former and can observe divergence only at the latter.
The comparison concerns completed may observations. It makes no classification
of noncompletion, and the singleton scheduler result concerns one thread.
General SC interleaving, Brookes shuffle, mutexes and race labels require
separate results.

## Typed institution stitch

The primary comparison uses Track A's existing store `R → Nat`.
The [concrete C2 API][c2] interprets a program over a fixed world with dependent
cell values and an owner map. To compare the shared lock-free fragment, take
`Cell := R`, `Value := fun _ => Nat`, `Mutex := Empty`, `Thread := Unit` and
`ExternalSort := Empty`. Embed memory using the unique empty owner map and
translate each transition endpoint through that store equivalence. Give each
primitive designation a single label and encode each read or write as a call
at its designation. Check the singleton generators with
`Concrete.primitive_accepts_iff`, using the equivalence between `Unit` and
`PUnit` for write replies.
Transport stuttering, mumbling and bind along the store equivalence, then
induct on `Code` with `Concrete.eval_ret` and `Concrete.eval_call_primitive`.
That gives full trace equality with concrete program evaluation. Composing with
`Concrete.eval_translate` gives the fixed-world, designation-preserving
translation and reduct statement for the embedding. This typed-store
transport and encoding are follow-up proof obligations.

```sh
lake build --wfail +Silmaril.Semantics.Brookes.TreeSC.Closed.Thms \
  +Silmaril.Proofs.Semantics.Brookes.TreeSC.Closed.Regression

lake env lean -DautoImplicit=false -DwarningAsError=true tests/semantics/brookes/TreeSCClosedAxioms.lean

for mod in Silmaril.Semantics.Brookes.TreeSC.Closed.Defs \
  Silmaril.Proofs.Semantics.Brookes.TreeSC.Closed.Code \
```
